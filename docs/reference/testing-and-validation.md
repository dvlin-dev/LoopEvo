# 测试与验证

## 验证原则

- 按风险执行最小充分验证，不为低风险变更运行无关的全量检查。
- 验证必须覆盖被修改的行为、关键失败路径和最可能受影响的边界。
- 测试通过只证明其覆盖范围内的行为，不自动证明外部平台、生产环境或文档事实仍然有效。
- 依赖账号、授权、网络、付费 API 或真实数据的验证应说明环境与范围，不用模拟结果冒充真实验证。
- 无法运行某项必要验证时，记录具体阻塞、剩余风险和可执行的后续检查。

## 风险分级

### L0：文档、知识库与静态原型

适用于：

- Markdown 内容和路径调整；
- `CLAUDE.md`、`AGENTS.md` 与文档导航；
- 不连接真实服务的 HTML 或静态原型；
- 注释和不影响运行行为的元数据。

最低验证：

- 检查完整差异和空白错误；
- 验证相对链接、符号链接、文件路径和目录职责；
- 检查事实、计划、原型和当前状态措辞是否混写；
- 对可渲染内容进行必要的人工查看。

### L1：局部行为与单一能力

适用于：

- 局部业务逻辑、UI 或 CLI 行为；
- 工作流定义、提示词、评估器或单个连接器；
- 不改变核心状态模型的 API 适配；
- 可在隔离环境中验证的浏览器交互。

最低验证：

- 运行目标单元测试或契约测试；
- 运行受影响范围的类型、Lint 或静态检查；
- 覆盖成功、无结果、输入错误、超时、限流和上游失败等相关路径；
- UI 或浏览器行为通过真实渲染或可重复的自动化步骤验证。

### L2：核心执行、安全与数据

适用于：

- 身份、权限、密钥和个人数据；
- 第三方生产数据访问和付费 API；
- 调度器、工作流运行时、队列、重试、幂等和状态迁移；
- 自动生成或自动发布代码；
- 数据删除、迁移、部署和回滚配置。

最低验证：

- 在 L1 基础上增加集成测试和端到端关键路径；
- 验证最小权限、秘密泄漏、审计记录和数据保留/删除行为；
- 验证重复执行、并发、部分失败、恢复、超时、限额和成本边界；
- 验证灰度、兼容性、回滚和灾难恢复路径；
- 发布前由具备权限的人员完成必要审批。

## 当前仓库的文档验证

项目尚无应用技术栈。当前纯文档变更使用以下真实可执行检查：

```bash
git status -sb
git diff --check
rg --files docs | sort
rg -n "docs/index\.md|archive/" CLAUDE.md README.md README.zh-CN.md docs
```

验证入口软链：

```bash
test -L AGENTS.md
test "$(readlink AGENTS.md)" = "CLAUDE.md"
test -L docs/AGENTS.md
test "$(readlink docs/AGENTS.md)" = "CLAUDE.md"
test -f "$(dirname AGENTS.md)/$(readlink AGENTS.md)"
test -f "$(dirname docs/AGENTS.md)/$(readlink docs/AGENTS.md)"
```

检查 Markdown 相对链接和旧路径引用：

```bash
rg -n '\]\((\./|\.\./)' README.md README.zh-CN.md CLAUDE.md docs
rg -n "旧路径" README.md README.zh-CN.md CLAUDE.md docs
```

这些命令不会自动证明文档业务事实正确。涉及实现状态、外部平台能力、价格、配额或条款时，仍需读取当前代码、官方文档或授权接口。

## 新技术栈落地后的维护

当仓库引入真实代码、构建和测试工具后，应在同一次交付中：

1. 更新 `docs/reference/repository-context.md` 的技术栈和入口；
2. 在本文件补充经过实际运行验证的安装、Lint、类型检查、测试和构建命令；
3. 定义本地、CI 和发布前检查的职责边界；
4. 删除已经失效的临时命令，不长期保留多个等价入口；
5. 保持风险分级，避免所有改动无差别执行最高成本验证。

## 交付记录

交付说明中的验证记录应使用事实表达：

```text
验证：
- 命令或步骤：实际执行内容
- 范围：覆盖的文件、模块、环境或场景
- 结果：通过、失败或受阻
- 未覆盖：没有验证的行为及原因
```
