# 安全与数据治理

## 适用范围

本规范适用于 LoopEvo 的工作流、连接器、Skills、MCP Server、API、浏览器操作器、Coding Agent、数据存储、评估和自进化机制。

设计阶段也必须遵守这些边界。尚未实现不代表可以推迟定义数据来源、权限、成本和不可逆行为。

## 数据访问

- 第三方平台数据必须通过官方 API、用户明确授权、有效商业合同或符合平台条款与适用法律的方式获得。
- 公开可见不自动等于允许批量收集、长期保存、训练模型或再次分发。
- 每个连接器必须声明数据来源、授权主体、允许用途、字段范围、地区限制、保留期限和删除方式。
- 不得通过绕过登录、验证码、访问控制、付费限制、速率限制或技术保护措施获取数据。
- 使用第三方数据供应商时，必须确认其数据来源、许可链路、服务条款、删除能力和责任边界。
- 平台 API、价格、配额和条款会变化；运行前应重新验证，不能只依赖历史文档。

## 连接器契约

每个连接器至少应公开：

- 所需权限、账号和授权方式；
- 可访问的对象、字段、时间范围和历史深度；
- 拉取、Webhook、流式或事件触发方式；
- 增量游标、去重键、幂等和断点续传语义；
- 速率限制、调用成本、延迟和配额；
- 超时、限流、授权失效和上游异常的错误模型；
- 数据保留、删除、导出和审计能力；
- 服务条款与地区限制的权威来源。

连接器不能通过静默降级隐藏覆盖率下降、授权失效或数据缺口。

## 密钥与身份

- API Key、Access Token、Refresh Token、Cookie、密码和私钥只能通过受控的秘密管理机制注入。
- 秘密不得进入源代码、提交历史、文档、提示词、日志、运行证据、截图或测试夹具。
- 不同环境、租户和连接器使用隔离身份；默认采用最小权限和最短必要有效期。
- 日志和错误信息必须脱敏，不能输出 Authorization Header、完整请求体或可复用会话信息。
- 凭据泄漏或授权撤销时必须能够定位使用范围、停止任务并轮换凭据。

## 个人信息与受许可数据

- 采集前明确目的、最小字段、合法依据、保留期限和访问角色。
- 原始内容、账号标识、画像、情感分析和跨平台关联可能构成个人信息处理，不能仅按普通文本对待。
- 用户应能了解系统监控哪些来源、保存什么数据、如何使用以及如何删除。
- 删除请求必须覆盖原始数据、派生产物、索引、缓存和可控备份；无法立即删除的范围应明确说明。
- 数据导出和分析结果不得扩大原授权用途，也不得泄漏第三方受限内容。

## 浏览器操作

- 优先使用官方 API 和结构化授权集成；只有 API 不足且操作被允许时才使用浏览器。
- 浏览器执行使用隔离环境、最小账号权限和明确的域名/动作白名单。
- 发布内容、发送消息、下单、付款、删除数据、修改账号和授权等高影响动作必须获得明确授权。
- 不在页面、截图、录屏和调试输出中保留令牌、Cookie、个人数据或商业敏感信息。
- 页面结构变化、登录失效或出现验证码时应安全停止，不能通过扩大操作范围盲目重试。

## Coding Agent 与生成模块

- Coding Agent 可以提出或实现缺失能力，但生成代码不能直接进入生产执行路径。
- 生成模块必须具备明确所有者、源码、依赖清单、权限、输入输出契约和版本。
- 必须经过与人工代码相同的代码评审、测试、安全扫描、秘密检查和许可证检查。
- 执行环境应隔离文件系统、网络、进程和资源配额；默认拒绝未声明能力。
- 自动生成新依赖或下载外部代码时，必须验证来源、完整性、许可证和供应链风险。
- 发布采用显式审批和可回滚版本，禁止运行时静默替换生产代码。

## 受治理的工作流进化

“自进化”必须遵循以下过程：

1. 使用运行证据、评估结果或明确反馈识别可衡量问题；
2. 生成独立、可审查的版本变更及预期收益和风险；
3. 在隔离环境中执行测试、历史回放、策略和预算校验；
4. 根据风险决定拒绝、人工审批或有限自动批准；
5. 通过灰度或受控范围发布；
6. 衡量新版本，退化时自动停止或回滚；
7. 保留版本、审批、证据和结果审计记录。

工作流定义、提示词、模型、信息源、过滤器、路由、评估器和能力代码都适用该过程。

## 成本与资源

- 工作流计划必须声明调用频率、预算、并发、最大重试和停止条件。
- 增量采集优先使用事件、Webhook、流式接口或可靠游标；轮询时根据来源新鲜度和价值设置自适应周期。
- 缓存、去重和批处理不能牺牲数据删除、权限变更和来源可追溯性。
- 成本异常、无限重试、事件风暴和下游积压必须触发限制或暂停，而不是继续消耗资源。

## 审计与事件响应

- 高影响动作记录操作者、工作流版本、授权依据、时间、目标和结果，不记录秘密本身。
- 数据访问和工作流执行应能追溯到来源、连接器版本和处理链路。
- 发现凭据泄漏、越权、错误采集或数据误发时，优先停止相关执行并保护证据。
- 事件处理至少覆盖影响评估、凭据轮换、数据隔离/删除、用户或合作方通知、修复验证和规则回写。

## 文档要求

涉及外部平台、用户数据或自动执行的新设计，必须明确：

- 数据与授权来源；
- 权限和秘密边界；
- 保留、删除和导出策略；
- 成本、配额和失败模式；
- 人工审批点和不可逆动作；
- 测试、灰度、停止和回滚路径。

缺少这些内容的设计不能进入生产实现。
